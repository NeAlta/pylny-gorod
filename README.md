# Пыльный город

Карточная вестерн-игра на 4–8 игроков для Android и iOS. Механики — как у классической
настольной «перестрелки с ролями» (шериф, помощники, бандиты, одиночка; дистанция, оружие,
персонажи со способностями). Названия, тексты карт, персонажи и оформление — собственные,
оригинальные имена и арт правообладателя не используются.

Игра идёт **только по локальной сети**: интернет и серверы не нужны.

## Что есть

- Базовая игра: 4 роли, 16 персонажей, колода из 80 карт.
- Дополнение «Новые рубежи» (включается в лобби): 14 персонажей, 32 карты, зелёные карты
  «запаса», карты с доплатой, игра до 8 человек.
- Хост-телефон ведёт партию; остальные подключаются к нему.
- Автопоиск столов в сети (Bonjour/mDNS) и запасной вход по IP-адресу.
- Переподключение: если игрок выпал из сети, он возвращается на своё место. Пока его нет,
  через 40 секунд за него делаются пропуски. Хост может пропустить ход за молчащего игрока.
- Скрытая информация честная: каждый телефон получает только то, что видит его игрок.
- Карты нарисованы кодом (без картинок), встроенные правила, журнал событий.

## Сборка

Нужно: **Flutter 3.32 или новее** (Dart 3.8+). Для iOS — Mac с Xcode, для Android — Android SDK.

```bash
cd pylny_gorod
dart run tool/setup_platforms.dart   # создаёт android/ и ios/, прописывает разрешения
flutter test                          # 400 случайных партий движка
flutter run                           # на подключённый телефон
```

Сборка для раздачи:

```bash
flutter build apk --release           # Android: build/app/outputs/flutter-apk/app-release.apk
flutter build ipa                     # iOS: нужна учётная запись Apple Developer
```

`setup_platforms.dart` добавляет:
- Android: разрешения `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE`,
  `CHANGE_WIFI_MULTICAST_STATE`.
- iOS: `NSLocalNetworkUsageDescription` и `NSBonjourServices` (`_pylgorod._tcp`) — без них iOS
  не даст искать столы и подключаться в локальной сети.

## Как играть по сети

1. Все телефоны в одной Wi-Fi сети. Нет роутера — один телефон включает точку доступа,
   остальные подключаются к ней (интернет не нужен).
2. Хост: «Создать стол». На экране стола виден его IP-адрес.
3. Остальные: «Присоединиться» — стол появится в списке. Если не появился (некоторые роутеры
   режут multicast, «гостевые» сети изолируют устройства) — ввести IP хоста вручную.
4. Хост выбирает базовую игру или с дополнением и нажимает «Начать партию».

Телефон хоста ведёт всю партию: ему не стоит сворачивать приложение или гасить экран надолго.
При первом запуске iOS спросит разрешение на доступ к локальной сети — его нужно дать.

## Устройство проекта

```
lib/
  engine/          чистый Dart, без Flutter
    cards.dart       карты и колода
    characters.dart  персонажи и роли
    game.dart        правила: ход, реакции, смерть, победа; viewFor() — вид для игрока
  net/
    protocol.dart    TCP, JSON по строкам, порт 47321
    discovery.dart   Bonjour-объявление и поиск столов (пакет bonsoir)
    session.dart     HostSession (сервер + движок) и ClientSession — общий интерфейс для экранов
  ui/              экраны: меню, поиск, лобби, игровой стол, правила
tool/setup_platforms.dart
test/engine_simulation_test.dart
```

Движок написан через `async/await`: когда нужно решение игрока, он отправляет запрос
(`turn` — действие в свой ход, `choose` — выбор из вариантов) и ждёт ответа. Хост проверяет
каждый ответ, поэтому подделать ход с клиента нельзя.

## Проверка

Логика движка прогнана на 4500 случайных партиях (4–8 игроков, с дополнением и без): без падений,
зависаний и потерь карт, сработала каждая карта и каждая способность. Тот же прогон есть в
`flutter test`.

Код собран без запуска Flutter-компилятора (в среде разработки не было SDK), его проверяли
построчным ревью. Если при первой сборке `flutter analyze` найдёт мелкие ошибки — они будут
точечными.
